# Changelog

[简体中文](CHANGELOG.md) | English

This file is the single source of truth for tack harness release notes:

- One section per release, heading format `## Vx.y.z (YYYY-MM-DD)`; entries are user-facing feature points tagged Added/Improved/Fixed instead of commit dumps
- `release.sh` verifies before releasing that the target tag has corresponding sections in both `CHANGELOG.md` (Chinese) and `CHANGELOG.en.md` (English); release aborts if either is missing
- CI extracts the corresponding sections from both changelogs and concatenates them as the bilingual GitHub Release body; the `check-update.sh` reminder and the `update` command's "What's new" view are sourced from both files

## V0.0.19 (2026-10-24)

- Added: The `auto` command (short `au`, triggers "auto / auto run / automatic execution / autopilot")—automatically runs the current workflow's remaining stages to its terminal state: it gathers missing inputs and confirms the whole flow once up front, then executes continuously without interruption and reports all key decisions and results at the end; defaults to merged / completed, optionally including close
- Added: Multi-project spaces with project-level knowledge isolation—the AGENTS.md project info is now a `projects` array, and work entries plus `status.yaml` record the owning project; project knowledge is read and written only under `wiki/<project>/`—capabilities go to the harness, project parameters to the project wiki, and workspace parameters to `status.yaml`
- Added: `close` automatically decides whether a requirement is worth archiving and writes the result to `wiki/<project>/history/<requirement>.md`; ask records are routed and archived as business terms, code navigation, code-external facts, project decisions, and requirement-specific background instead of being copied verbatim
- Added: Task/deploy state machines and the Git fact layer—`work-status.sh` gains tasks / guidance / deploy subcommands (task dependency validation, readiness listing, deploy upsert and status writeback); new `git-facts`, `git-commit-helper`, `git-push-helper`, `harness-diff`, and `harness-backup`; `work.sh rename` becomes a transaction with rollback; `scan-secrets --changed` is wired into space auto-commit
- Added: Safe branch cleanup via `branch-clean.sh`—dry-run by default, only branches registered in `status.yaml` are touched, and after an automatic fetch it prefers `origin/<mainline>` to judge merge status; unmerged main branches, protected branches, branches occupied by worktrees, and cases with an unclear mainline are only listed and never deleted, and remote branches are never deleted automatically; `close` now performs cleanup through this script
- Added: Document-vs-script call-signature checking via `lint-doc-scripts.sh` (script existence, fixed subcommands, required positional arguments, and explicit flags; runs alongside `lint-harness`) and `run-plan.sh check` (read-only validation of the `run.md` checklist, scripts, required files, and dependency order)
- Added: `common.sh` unifies shared install/upgrade capabilities (agent presets, distribution list, download fallbacks, version extraction, SHA-256 verification); `install.sh` resolves the latest Release by default and enforces SHA-256 verification, with a new `--branch` development entry; Releases now produce tar.gz plus .sha256; CI adds `sh -n`, three lints, and a three-platform matrix
- Improved: `merge` becomes a pure branch merge—after fetching the latest, it merges the local/remote source into the target branch, routes conflicts to `solve`, and commits and pushes when done; when the current workspace is the source branch, a linked workspace is created and records `parent_workspace`, and `close` closes linked workspaces in cascade
- Improved: `spec` / `plan` / `tech-design` positions are aligned—`spec` becomes the top-level design and public contract (product/test decisions close in this stage), `plan` becomes the detailed design and construction blueprint (interfaces/SQL/verification/rollout/task dependencies), and `tech-design` becomes an on-demand stage that only reorganizes the confirmed spec/plan for a formal review without adding design decisions
- Improved: `update` now decides `rule/` files one by one with the user (take the new version / keep local / merge); undecided files stay as-is—never silently skipped or auto-overwritten; newly added rule files are distributed normally as ADDED
- Improved: Git standards are split into `git-standards.md` (branch naming, commit messages, code review, and related prohibitions); `coding-standards.md` adds function cohesion, reduced nesting, single-fetch data sources, and exception-logging requirements; `coding-standards-shell.md` crystallizes absolute-path normalization, post-deletion verification, NUL handling for special filenames, glob enumeration, keeping runtime values out of sed addresses, flags in any position, a single source of truth for shared logic, and fixed C locale for BSD awk
- Fixed: Workspace directories flatten `/` in branch names to `-` (git branches keep `/`), with corresponding fixes in `work` / `project` / `scan-routes` / `work-status`; `rm -rf` false success on relative paths, `scan-secrets` missing filenames containing Chinese, spaces, or quotes, and routing failures for group names containing spaces are all fixed
- Fixed: `deploy` upsert replaces the whole entry when the `(repo, env, lane)` compound key matches, avoiding duplicates; space-repository auto-commit being blocked by an extra pathspec is fixed; `work-status` state values converge to `pending/applied/rejected`
- Fixed: macOS BSD awk fails with a `towc` multibyte conversion when reading long Chinese lines under a UTF-8 locale; structural parsing in `lint-harness` and `lint-doc-scripts` now pins `LC_ALL=C`
- Improved: Docs and site—the project wiki template converges on semantics/reasons/conventions/query entry points; site assets move to `docs/`; both READMEs gain capability scope, project wiki structure, and new command documentation; contact adds the Douyin group (group number 978398534393) and a dual-group QR code; CI upgrades actions/checkout to v5

## V0.0.17 (2026-10-12)

- Added: close now fully deregisters a workspace at finalization—after removing worktrees and cleaning branches per the branches register, `work.sh purge` deletes the whole `space/<workspace>/` directory and `project.sh work-remove` removes the work entry from the AGENTS.md project-info block (process documents are not kept; cross-workspace knowledge has already been distilled into wiki/harness). purge enforces three safety gates: a single-segment directory name only (no separators, whitespace, or `.`/`..`), the physical target path confirmed via `pwd -P` to reside inside `space/` (symlink-escape protection), and no valid worktree left under `repo/`; deletion is rejected if any gate fails. Interrupted finalization resumes from breakpoints (worktree already removed, or directory gone while the entry remains)
- Added: evolution gains a "workspace registration reconciliation" step (new step 3)—`project.sh` gains three subcommands `work-reconcile` / `work-remove` / `work-path`: reconcile compares AGENTS.md work entries against the actual `space/` directories (report only, zero writes) and outputs four diff types—MISSING_DIR (entry exists, directory missing → remove the orphan entry), UNREGISTERED (directory exists, no entry → re-register from the status.yaml summary), STALE_COMPLETED (legacy close archive residue → purge and remove after confirmation), PATH_MISMATCH (registered path differs from disk → recalibrate via work-path using the actual directory); each fix lands through scripts after per-type user confirmation. Workspace listing and switching now use AGENTS.md registrations as the sole source of truth instead of scanning the disk
- Improved: The development workflow terminal state changes from "marked completed" to "deregistered by close"—state transitions end at merged, and close removes both the workspace directory and its registration; close no longer writes the unconsumed cleaned status or asks whether to keep process documents, and the deletion is recorded by the unified finalization commit
- Improved: Execution-efficiency discipline is crystallized—the shipped tack/AGENTS.md gains core constraint #14 "save roundtrips and context" (locate via grep/glob and read only matched snippets; issue independent searches and reads in parallel in one round; trim list/scan output on the shell side; map related edits in a file before block-replacing them; confirm the full blast radius before delete/archive/rename actions); the source-repo AGENTS.md gains a developer-facing "Execution efficiency discipline" section (six rules covering clarifying connected semantics first, minimal E2E cases, and using the Git for Windows sh.exe absolute path directly on Windows)

## V0.0.13 (2026-10-03)

- Added: The `code-review` command (short `rv`, triggers "code review / review report")—using `plan.md`/`tech-design.md` as the spec and the three-dot diff against the target branch as facts, it analyzes changes function by function along "repository → file → function" (with code anchors), logic correctness, obvious bugs, and code-level hazards (security/performance/compatibility), and assesses affected interfaces and business scenarios, producing the standalone report `$work/code-review.md`; large cross-module changes can be delegated to the code-reviewer for three perspectives in parallel, and the `merge` gate may reuse the report's conclusions when the review baseline is identical
- Added: The `release-check` go-live checklist command (short `rc`, triggers "release check / go-live check")—item by item it identifies database changes (with executable migration and rollback statements, target environments and timing), config changes (with key/value example/environment templates), new outbound API calls (permissions and allowlists to request), and new middleware (resources to provision in advance), plus backstops such as scheduled jobs, credentials, canary rollout, and rollback plans, producing `$work/release-check.md` as an itemized checklist plus a suggested go-live order
- Added: The shared script `git-diff-context.sh`—resolves the target branch (local first, then origin/ fallback, auto-detects master/main), computes the merge-base, and exports the three-dot diff and its statistics, providing deterministic facts for review commands; E2E covers local-only / remote-only / no-diff / error paths
- Added: Unified Hook logging—with `TACK_HOOK_LOG=1`, every invocation of the three Hooks records the full payload: time, event, pid, cwd, environment variables, raw input payload, raw injection/interception output, exit code, and duration to `.tack/log/hook.log` (a mutex lock appends whole blocks serially so concurrent writes never interleave); when logging is off, Hook output is byte-for-byte unchanged
- Improved: `TACK_ROOT`/`TACK_WORK` are wired into actual consumption—the environment variables only act as a SessionStart cache, and before use the space marker, path containment, and workspace state (not completed) are validated, with automatic fallback to real-time probing when invalid; UserPromptSubmit/PreToolUse save repeated upward probes and full space scans

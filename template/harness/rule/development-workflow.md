# 开发流程说明

> 定义需求无关的通用开发流程。团队可在此自定义步骤。

## 标准开发流程

```
1. 需求初始化  →  /tack new-req <branch>
2. 需求输入    →  /tack req-context <prd>
3. 需求分析    →  /tack analyze-req
4. 任务拆解    →  /tack breakdown
5. 迭代开发    →  /tack develop
6. 需求修正    →  /tack fix-req (按需)
7. 单测编写    →  /tack unit-test (可选)
8. 交付        →  (部署 + 归档)
```

## 各环节说明

### 1. 需求初始化
- 创建分支文件夹
- 初始化 status.yaml
- 创建子目录结构
- 自动创建 git worktree（如 `repo/` 下已有 git 仓库）

### 2. 需求输入
- 接收 PRD 文档
- AI 整理为结构化 wiki
- 人工审阅确认

### 3. 需求分析
- AI 分析需求，生成技术设计文档
- 对不清晰的地方提问用户
- 输出技术设计到 harness/

### 4. 任务拆解
- 将技术设计拆为独立子任务
- 标注任务间依赖关系
- 每个任务对应一个交付物

### 5. 迭代开发
- 前置条件：只有执行完任务拆解（breakdown）并生成任务清单后，才能进入此阶段
- 按依赖关系逐任务实现
- 每个任务完成后暂停审核
- 使用 TDD 方式开发
- 所有代码改动只能在 `work/<branch>/repo/` 下进行（git worktree），禁止直接修改根目录的 `repo/`

### 6. 需求修正
- 开发中发现需求问题时触发
- 回写技术文档和任务清单
- 重新评估影响范围

### 7. 单测编写
- 可选阶段
- 为核心逻辑补充单元测试
- 使用 TDD 循环

### 8. 交付
- 代码审查通过
- 部署到目标环境
- 归档文档

# To Tickets — 任务拆解

将计划、技术设计或对话拆分为一组**任务清单**：tracer-bullet 垂直切片，每个任务声明它**阻塞**了哪些其他任务。

## 过程

### 1. 收集上下文

从对话上下文中已有的内容开始工作。

### 2. 探索代码库（可选）

如果尚未探索代码库，请先探索以理解代码库的当前状态。任务标题和描述应使用项目的领域术语。

寻找机会进行预重构（prefactoring），使实现更容易。"让改变变得容易，然后做出容易的改变。"

### 3. 起草垂直切片

将工作拆分为 **tracer bullet** 任务。

**垂直切片规则：**
- 每个切片狭窄但**完整**地穿过每一层（schema、API、UI、测试）：是垂直的，不是某层的水平切片
- 已完成的切片可以单独演示或验证
- 每个切片大小适合单个上下文窗口
- 任何预重构应首先完成

给每个任务标注其**阻塞边缘**：必须在它之前完成的其他任务。没有阻塞的任务可以立即开始。

**大范围重构例外：** 大范围重构是一种机械性变更（如重命名列、重新类型化共享符号），其爆炸半径跨越整个代码库。使用 expand-contract 模式：先添加新形式（expand），然后批量迁移调用点（migrate），最后删除旧形式（contract）。

### 4. 询问用户

将提议的分解呈现为编号列表。对每个任务，显示：
- **标题**：简短描述性名称
- **阻塞**：哪些其他任务必须先完成
- **交付内容**：该任务实现的端到端行为

询问用户：粒度是否合适？阻塞边缘是否正确？是否需要合并或拆分？

### 5. 输出到 plan/

将批准的任务清单写入 `work/<branch>/plan/tasks.md`，使用以下格式：

```markdown
# 任务清单

## 01: <任务标题>
**交付内容**: <端到端行为>
**阻塞**: 无（可立即开始）
- [ ] 验收标准 1
- [ ] 验收标准 2

## 02: <任务标题>
**交付内容**: <端到端行为>
**阻塞**: 01
- [ ] 验收标准 1
```

# TDD — 测试驱动开发

TDD 是 红 → 绿 → 重构 循环。本参考确保该循环产生值得保留的测试。

## 什么是好的测试

测试通过**公共接口**验证行为，而不是实现细节。代码可以完全改变；测试不应该。好的测试读起来像规范——"用户可以用有效购物车结算"告诉你存在什么能力——并在重构后存活，因为它不关心内部结构。

## 接缝 — 测试的位置

**接缝**是你测试的公共边界：你观察行为而不进入内部的接口。测试生活在接缝处，从不针对内部。

**只在预约定的接缝处测试。** 在写任何测试之前，写下正在测试的接缝并与用户确认。

## 反模式

- **实现耦合** — mock 内部协作者，测试私有方法，通过侧通道验证。标志：重构时测试会破坏，但行为没有改变。
- **重言式** — 断言以与代码相同的方式重新计算期望值。期望值必须来自独立的事实来源。
- **水平切片** — 先写所有测试，然后写所有实现。改为使用**垂直切片**——一个测试→一个实现→重复。

## 循环规则

- **红先于绿。** 先写失败的测试，然后只写足够的代码通过它。
- **一次一个切片。** 每个循环一个接缝、一个测试、一个最小实现。
- **重构不是循环的一部分。** 它属于审查阶段（参考 `resources/code-review.md`）。

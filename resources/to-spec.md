# To Spec — 生成技术设计文档

将当前对话上下文和代码库理解转化为技术设计文档。**不要访谈用户**；只需综合你已知的内容。

## 过程

1. 如果尚未探索代码库，先去探索。使用项目的领域术语，参考 `wiki/business-understanding.md`。
2. 勾勒出测试功能的**接缝**。优先使用现有接缝。接缝越少越好——理想数字是一个。
3. 使用下方模板编写技术设计文档，保存到 `work/<branch>/harness/tech-design.md`。

## 技术设计模板

```markdown
## 问题陈述
从用户角度描述用户面临的问题。

## 解决方案
从用户角度描述问题的解决方案。

## 用户故事
极其详尽的编号列表，覆盖功能的所有方面。

1. 作为 <角色>，我想要 <功能>，以便 <收益>

## 实现决策
- 将构建/修改的模块
- 那些模块的接口
- 技术澄清
- 架构决策
- Schema 变更
- API 契约
- 具体交互

## 测试决策
- 什么是好的测试（只测试外部行为，不测试内部实现）
- 哪些模块将被测试
- 现有测试的参考

## 范围外
描述此设计范围外的内容。

## 进一步说明
关于该功能的进一步说明。
```

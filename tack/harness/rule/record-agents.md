# 沉淀 harness 常驻约束（AGENTS.md）规则

> 被 `record` 命令引用：类型判定为 agents 时，按本文件落盘。

## 落点

- `$root/AGENTS.md` 的「tack harness 核心约束」编号条目

## 适用范围（先判断，再落盘）

- 仅限**对本 tack 空间所有项目都成立**、必须常驻上下文的行为约定与环境约束（如「本机执行 harness 脚本必须走 run.ps1」「严禁对空间根执行 git」）
- **项目级常驻约定**（某项目的提交规范、环境约定、网关/账号使用规则等）→ `$root/wiki/<project>/decisions.md` 的「工程约定」，不进共享 AGENTS.md
- 编码规范、评审要求 → `harness/rule/`
- 判断标准：换一个项目是否仍然成立？否 → 项目 wiki；是 → 核心约束

## 落盘方式

- 先匹配现有核心约束编号条目：已表达相同约束的**就地融合**（替换表述、必要时补日期），不重复新增
- 确无对应条目时，追加为新的编号条目，保持编号连续
- 条目须明确、可执行，避免口号式描述

## 边界（禁止项）

- 不得修改 `<!-- tack:info:start -->` 与 `<!-- tack:info:end -->` 之间由 project.sh 维护的 YAML 区块
- 不得改动命令路由、环境变量与目录概览等 harness 固定章节
- 不把项目级参数、易变事实或一次性过程信息写入核心约束

## 生效

- 展示落盘内容，**必须经人工审阅确认后才可作为上下文**

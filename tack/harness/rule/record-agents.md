# 沉淀 AGENTS.md 常驻约束规则

> 被 `record` 命令引用：类型判定为 agents 时，按本文件落盘。

## 落点

`$root/AGENTS.md` 的两个约束分组：

| 分组 | 收什么 |
|------|--------|
| AGENT 核心约束 | 跨命令、跨工作区都成立的模型行为约定（语言、事实来源、读取纪律、并行、引用方式等） |
| tack harness 核心约束 | 本 tack 空间特有的行为边界（工作区与项目确认、Git 双层边界、知识落点、沉淀生命周期等） |

## 适用范围（先判断，再落盘）

- 仅限**对本 tack 空间所有项目都成立**、必须常驻上下文的约定。
- **项目级常驻约定**（某项目的提交规范、环境约定、网关/账号使用规则等）→ `$root/wiki/<project>/rule/conventions.md`。
- 编码规范、评审要求 → `harness/rule/`。
- 判断标准：换一个项目是否仍然成立？否 → 项目 wiki；是 → 常驻约束。

## 落盘方式

- **先查命令文件**：该约束若只对某个命令/流程生效，写入对应 `harness/cmd/` 或 `harness/workflow/` 文件，不放常驻约束。
- 常驻约束**按名称匹配**现有条目（如「工作区与项目确认」「Git 双层边界」「沉淀生命周期」），已表达相同约束的就地融合，不重复新增。
- 确无对应条目时，追加到对应分组；值得细化的长规则下沉 `harness/rule/`，常驻处只留一行引用。
- 条目须明确、可执行，避免口号式描述；不使用「第 N 条」编号。

## 边界（禁止项）

- 不得改动「命令路由」「脚本调用约定」「数据来源」「目录概览」等固定章节。
- 不把项目级参数、易变事实或一次性过程信息写入常驻约束。
- 不把已存在于 cmd/workflow/rule 的流程细节复制到常驻约束，只保留引用。

## 生效

- 展示落盘内容，**必须经人工审阅确认后才可作为上下文**。

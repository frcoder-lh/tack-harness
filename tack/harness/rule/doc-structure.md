# 结构化文档组织规则

> 审视和优化 AGENTS.md、rule、cmd 指令、workflow 等结构化 markdown 时的组织原则。被 `record` / `evolution` 命令或人工审视文档结构时加载。

## 适用范围

- `tack/AGENTS.md`、`harness/rule/`、`harness/cmd/`、`harness/workflow/` 下含编号条目或章节层级的 markdown
- 同样适用于用户空间沉淀后的 `AGENTS.md` 常驻约定区块

## 组织原则

1. **定义前置**：变量/术语/缩写的定义出现在首次使用之前。若某节引用了靠后才定义的符号（如 `$root`/`$work`），把定义节前移到首次使用之前；无法前移时在引用处加内联说明，不留给读者猜。
2. **同类聚拢**：同一主题或同一生命周期的条目相邻，避免被无关内容打散。若发现同一流程链的条目被隔断（如"采集→触发→固化"被其他条目分隔），重排使它们相邻，读者顺序阅读即可拼出全貌。
3. **时间序排列**：有流程关系的条目按实际发生顺序排——采集→触发→固化、前置条件→动作→后置校验、手动→自动等。跨条目引用链应尽量变成顺序阅读路径，而非跳读。
4. **引用同步**：重排编号条目（有序列表）时，必须同步检查并更新所有跨条目/跨章节/跨文件的编号引用。重排前先 `grep` 整个 `harness/`（含 `tack/AGENTS.md`、`harness/cmd/`、`harness/workflow/`、`harness/template/` 等）"第 N 条""见第 N 条"式引用，重排后逐一核对，避免悬空指向——跨文件引用同样会悬空，只 grep 当前文件会漏。

## 验证

- 重排后 `grep` 整个 `harness/` 的"第 N 条"等编号引用，确认无悬空指向（被引用的条目编号仍存在且语义对应）；仅 grep 当前文件会漏跨文件引用
- `git diff --stat` 抽查是否整文件脏 diff（LF 换行问题，详见 `windows-env.md`）

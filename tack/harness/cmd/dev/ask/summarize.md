# ask 流程：总结已有讨论

> 目标：复用已有结论，最短路径输出总结；只有产生新结论时才落盘。

## 1. 定位并读取结论（一轮并行）

- 按 `$work/doc/analysis/` 目录扫描 `.md`，按头部「主题」与标题匹配；同时读取 `$work/status.yaml` 的 project/workflow
- 只读目标文档的「梳理结论」「问答记录」与头部（主题、基准 commit、最近更新），不整文件通读
- 结论缺少依据或用户要求核实时，才读取必要的代码片段；不重新全量检索仓库与 git history

## 2. 输出简洁总结

- 按主题归纳：已有结论、证据状态（已证实 / 待确认）、未决问题
- 只讲结论与必要依据，不复述问答过程，不重复文档全文
- 结论与当前代码可能冲突时，注明「文档基于 <基准 commit>，当前 HEAD 为 <hash>」

## 3. 有新结论才更新文档

- 总结产生新结论或纠正旧结论时，把变化融合进目标文档「梳理结论」，更新「最近更新」与「基准 commit」
- 未产生新结论时不改文档，不追加重复问答记录
- 证据不足或结论已过时：转入「核实既有结论」或「回答新问题」流程，不在总结分支重新全量检索

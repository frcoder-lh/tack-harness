# ask 流程：回答新问题

## 1. 判断事实类型与检索入口

- 按 `harness/rule/wiki-read.md`「检索准确性」：
  - 词频/统计 → 聚合函数；主题/标签来源 → 生产者与写入点；查询支持条件 → 请求参数与查询构造器
  - 精确符号优先（函数名、RPC、字段名、常量名），普通业务词只用于找入口
  - 复杂正则无命中时先用字面量复查；默认排除测试与生成代码
- 问题过宽（如「讲讲这个项目」）时先追问聚焦，或转入「整体分析」流程

## 2. 一轮并行检索

- 按「明确文档路径 → 当前主题文档 → 项目索引 → 历史归档 → 代码补查」收集信息；文档与代码路径先确定，再搜索
- 代码检索顺序：`$work/repo/<repo-name>/` 优先，缺失时 `$root/repo/<repo-name>/`（只读）
- 先限定仓库、目录与生产文件，再搜精确符号；无命中时逐级扩大范围，不因一次无命中断言不存在
- 搜索命中只用于定位，不当作结论

## 3. 读取证据并形成结论

- 关键结论必须读取函数体、调用方或数据结构对应片段；结论与证据逐项对应，一段代码不能同时证明多个无关判断
- 否定结论写明检查了哪些调用链、写入路径与仓库/目录/符号
- 读不到依据的部分标「待确认」，不臆测

## 4. 定位主题文档

- 扫描 `$work/doc/analysis/*.md`，读取各文档头部的「主题」与标题，判断问题是否属于已有文档；不按固定文件名或 `-analysis` 后缀匹配
- 命中同一主题：在该文档中追加（见第 5 步）；存在多个相近文档无法确定时，列出候选请用户选择
- 无匹配：新建文档，文件名按主题提炼英文 kebab-case（如 `order-timeout-flow.md`，遵守 `harness/rule/naming.md`），写入 `$work/doc/analysis/`（必要时先 `mkdir -p`）；用户可改名
- 新文档初始结构：

  ```markdown
  # <中文主题>

  > 主题: <主题关键词>
  > 涉及仓库: <repo1, repo2>
  > 基准 commit: <short-hash>
  > 最近更新: <日期>

  ## 梳理结论

  （问答中持续融合更新的结论区）

  ## 问答记录
  ```

## 5. 回答并融合文档

- 当场向用户输出回答，关键结论附 `仓库/路径#L12-L15` 依据
- 在「问答记录」下追加 `### Q<n>: <问题>（<日期>）` 与回答（含依据锚点）
- 同步更新「梳理结论」：新结论融合进已有表述，重复内容合并、结论变化就地更新，不堆叠矛盾说法
- 更新头部「最近更新」「涉及仓库」，并按当前 HEAD 更新「基准 commit」；发现 HEAD 已偏离文档基准时先提示早期结论可能基于旧代码
- 边界: 主题文档留在 `$work/doc/analysis/`，不登记长期索引；易变实现细节不提炼成锚点，用户确认有稳定导航价值时走 `record`；关闭工作区时由 `close` 按 `harness/rule/archive-ask.md` 转化归档

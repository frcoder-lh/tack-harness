# Grilling — 深入访谈

对用户进行持续深入的访谈，直到达成共识。将问题映射为**设计树**：每个决策分支挂着依赖它的其他决策。

## 工作方式

按**轮次**工作。**前沿（frontier）**是指所有前置条件已解决的决策：即那些现在可以提问而无需猜测尚未听到答案的问题。每一轮一次性问完所有前沿问题：给每个问题编号并附上你的推荐答案。然后等待用户回答后再进入下一轮。

## 轮次格式

```
❓ **Q1** - **<问题标题>**: <问题内容，可能多段，包含多个选项>
➡️ <你的推荐答案>
---
❓ **Q2** - **<问题标题>**: <问题内容>
➡️ <你的推荐答案>
```

每轮用户的回答会重塑设计树：已解决的决策推动前沿向外扩展，解锁依赖它们的问题。重新计算前沿并提出下一轮问题。一个问题的答案依赖于本轮中另一个尚未解决的问题时，应归入**后续**轮次。

## 执行规则

- **事实查找是你的职责**，永远不是用户的。当前沿问题需要来自环境的事实（文件系统、工具等）时，派遣子 agent 去查找；不要向用户询问你能自己查到的东西。不要阻塞：正在进行的探索是未解决的前置条件，所以只有下游的问题等待子 agent 报告；立即询问其余前沿问题。
- **决策由用户做出**：把每个决策交给他们并等待。
- 会话在前沿为空时结束：设计树的每个分支都已访问，没有默默假设的内容。在用户确认已达成共识之前，不要采取行动。

## 领域模型集成

在访谈过程中，当术语被澄清或决策被确认时，同时更新项目的领域文档（对应 `wiki/` 下的术语表和 `harness/` 下的技术决策）。

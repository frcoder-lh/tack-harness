# Codebase Design — 代码库设计

设计**深度模块**：小接口背后承载大量行为，放在干净的接缝处，可通过接口测试。在设计或重构代码时使用这套语言和原则。

## 术语表

**模块（Module）**：任何有接口和实现的东西。刻意与规模无关：函数、类、包或跨层切片。

**接口（Interface）**：调用者必须知道的所有内容才能正确使用模块：类型签名，还有不变量、排序约束、错误模式、所需配置和性能特性。

**实现（Implementation）**：模块内部的代码体。与**适配器（Adapter）**区分：一个事物可以是适配器（大实现）或大适配器（小实现）。

**深度（Depth）**：接口处的杠杆作用。调用者（或测试）每单位接口能练习的行为量。

**接缝（Seam）**（Michael Feathers）：你可以在不编辑该位置的情况下改变行为的地方；模块接口所在的*位置*。

**适配器（Adapter）**：满足接口在接缝处的具体事物。描述*角色*（填什么槽），而不是内容。

**杠杆（Leverage）**：调用者从深度中获得的收益。每个接口单元学习更多功能。

**局部性（Locality）**：维护者从深度中获得的收益。变更、bug 和知识集中在一处。

## 深度 vs 浅层

**深度模块** = 小接口 + 大量实现

```
┌─────────────────────┐
│   小接口             │  ← 少量方法，简单参数
├─────────────────────┤
│                     │
│  深度实现            │  ← 隐藏复杂逻辑
│                     │
└─────────────────────┘
```

**浅层模块** = 大接口 + 少量实现（避免）

## 原则

- **深度是接口的属性，不是实现的属性。** 深度模块可以由小的、可 mock 的、可替换的部件内部组成。
- **删除测试。** 想象删除模块。如果复杂性消失，它就是个传递器。如果复杂性在 N 个调用者中重新出现，它就在发挥作用。
- **接口是测试表面。** 调用者和测试跨越同一个接缝。
- **一个适配器意味着假设的接缝。两个适配器意味着真正的接缝。**

## 可测试性设计

1. **接受依赖，不要创建依赖。**
2. **返回结果，不要产生副作用。**
3. **小表面积。** 方法越少 = 需要的测试越少。

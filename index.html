Design Principles

与将流程固化的现有 AI 编码工具不同

Tack Harness 不把开发流程写死成模板，而是让流程本身可以被固定、被扩展、被追踪、被隔离、被沉淀。

01

流程可固定

凡可由脚本完成的操作均不依赖大模型，通过固定流程脚本保证稳定性并控制 token 成本。

02

能力可扩展

新增一个 Markdown 文件即注册一条新能力，无需修改 skill 本体，升级不覆盖。

03

状态可追踪

工作区 status.yaml 为唯一有状态文件，AI 可随时明确当前进度与下一步操作。

04

改动可隔离

通过 worktree 隔离各需求的代码改动，主仓库始终保持只读基准。

05

经验可沉淀

每个完成的任务自动将实践经验沉淀为命令、工作流、规则或 wiki 条目。

Core Features

一套命令，驱动完整研发链路

依赖注入、状态机、缺陷溯源、门禁审查、命令自创造、自进化……每一个环节都为「少消耗、可复现、可追溯」而设计。

依赖注入

skill 为容器、能力为注入物。命令、工作流、可委派角色均为项目内的 Markdown 文件，文件头即注入声明，scan-routes 运行时动态扫描装配路由表。新增一个文件即注入一条新能力。

commandshorttriggersscan-routes

工作流状态机

开发、测试、缺陷修复、冲突合并、分支操作各有独立工作流，定义状态流转并编排命令。status.yaml 的状态由工作流定义，AI 始终明确当前阶段与下一步。

developmenttestingbugfix

缺陷溯源

bugfix 工作流内置 git-bug-trace：定位缺陷代码行后一键追溯引入 commit、时间、作者、对应需求/工单 ID 与 MR 链接，区分需求引入与历史遗留。

git-bug-tracebug_origin

审查与上线门禁

code-review 以方案为规范、三点 diff 为事实逐函数审查；release-check 产出上线检查清单——数据库变更、配置模板、接口权限、中间件资源，逐项打勾后发布。

code-reviewrelease-check

命令自创造

record 是「生成指令的指令」。先扫描已有命令尝试融合修正；若无合适命令，仅需提供 command，简写、中英文触发词与命令正文自动生成。

record自动生成

自进化

guidance 闭环：任务各环节自动把用户引导以原始事实追加到 status.yaml，close 时审查固化到 workflow/cmd/rule，经 check-guidance 校验，形成「采集 → 固化 → 校验」回路。

guidancecheck-guidance

角色委派

内置可委派角色 code-explorer / code-architect / code-reviewer，被 ask、plan、tech-design、code-review、merge 等命令引用后经 Task 子代理在独立上下文并行执行。

code-explorercode-architectcode-reviewer

自动更新检查

close / evolution / record / help 收尾时静默检查新版本（7 天 + 同版本双节流），发现新版本即展示本机到最新版本的全部更新内容，确认后说「更新」即可升级。

closeevolutionupdate

向外学习

study 把外部 skill 或仓库当作教材：通读结构、提炼可借鉴点、以新增/融合/优化方式落盘到 harness，统一预览确认后自动提交并触发一次 evolution 向内自审。

studyevolution
Workflow

从空目录到需求上线的完整链路

工作流由「状态机 + 命令编排」构成。AI 收到指令后先确认当前工作，再识别意图所属工作流，按状态流转引导命令。测试类命令为按需触发，不阻塞主链路。

1/tack init→ 2/tack work→ 3/tack spec→ 4/tack plan→ 5/tack code→ 6/tack commit→ 7/tack push→ 8/tack merge→ 9/tack close
主链路之外：/tack testcode · /tack test · /tack run 按需触发；/tack fix · /tack solve 在偏差与冲突时介入。

Installation

四种方式，一分钟上手

推荐由 agent 自行安装。无论小规模项目还是大型项目，都能从规范化的研发链路中受益。

1由 agent 自行安装推荐

在 TRAE 中输入一行指令，agent 会自动安装这个 skill 并完成环境准备。

# 在 TRAE 中输入
Install this skill: https://github.com/frcoder-lh/tack-harness
2一键安装脚本

通过 curl 管道直接执行安装脚本，适用于快速接入任意环境。

curl -fsSL https://raw.githubusercontent.com/frcoder-lh/tack-harness/master/install.sh | sh -s

Windows Git Bash 下若报 CRYPT_E_NO_REVOCATION_CHECK，在 curl 后加 --ssl-no-revoke 即可。

3克隆后安装

克隆仓库后执行 install.sh，支持交互式安装与指定 agent 目标。

git clone git@github.com:frcoder-lh/tack-harness.git
cd tack-harness
sh install.sh                        # 交互式安装
sh install.sh --agent trae           # 安装到 TRAE
sh install.sh --list                 # 查看支持的所有 agent
4Releases 下载压缩包

无法使用 Git 克隆，或希望安装固定版本时，从 Releases 下载解压后执行安装脚本。

mkdir tack-harness
unzip tack-harness-V0.0.1.zip -d tack-harness
cd tack-harness
sh install.sh
Security Model

安全可控，从机制上保证

worktree 隔离改动、命令准入准出、人工审阅关口、凭据明文拦截——把风险挡在流程之外。

worktree 隔离

代码改动仅限工作区 worktree，主仓库 repo/ 始终为只读基准，多个 agent 并行互不干扰。

Git 双层边界

空间根仓库由框架自动提交托管，用户 Git 命令仅作用于工作区代码仓库。

命令准入准出

破坏性 Git 操作被禁用，命令执行受准入准出约束。

人工审阅关口

分析结论、合并均需人工确认后方可生效；提交由用户主动发起 commit 命令触发。

凭据明文拦截

scan-secrets.sh 在空间文档提交前做高置信凭据扫描，命中即阻断自动提交；支持豁免标记与占位值过滤。

落点证据链校验

check-guidance.sh 校验 guidance distilled 条目落点文件仍然存在，失效即阻断 close，防止固化证据链悬空。
